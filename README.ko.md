# ui-picker

UI를 만들기 전에 먼저 묻는 Claude Code 플러그인. 요청의 모든 영역을 25개 UI 용어 중 하나로 이름 붙이고, 어울리는 패턴 후보를 애니메이션 미리보기로 보여주고, 구조가 달라지는 곳에서만 질문하고, 숫자를 고치게 한 뒤, 네가 승인한 한 화면짜리 명세를 모델에게 넘긴다.

질문한 언어로 답한다. 한국어로 물으면 패널도 한국어.

![질문 1/1: 메뉴 영역 후보 3개가 움직이는 미리보기](docs/ask.png)

## 왜

- "메뉴 부분은 멋지게"라고 하면 모델은 아무거나 고른다. ui-picker는 카드 레이아웃·벤토 그리드·탭·캐러셀을 나란히 움직여 보여주고 숫자 키 하나로 고르게 한다.
- 패턴이 둘 이상 진짜로 어울릴 때만 묻는다. 상단 내비, 히어로, 로딩 상태는 알아서 정하고 목록에만 올린다.
- 모든 행에 기본 동작·키보드 규칙·모바일 대응이 붙어 있어서, 일일이 말하지 않아도 빌드가 일관된다.
- 승인한 계획은 모델이 다르게 해석할 수 없는 한 줄로 전달된다: `- 빵 메뉴: Bento Grid (네 선택) · cols 3`.

## 설치

Claude Code 안에서 (2.1.303 이상, 터미널):

```
/plugin install ui-picker --marketplace rudxognss/ui-picker
```

범위 고르고 Enter. 재시작 없음.

![Claude Code 안의 설치 다이얼로그](docs/install.png)

셸: `claude plugin install ui-picker --marketplace rudxognss/ui-picker`

스킬만 쓰기 (`SKILL.md`를 읽는 어떤 에이전트든: Cursor, Codex, 패널 없는 Claude Code): `npx skills add rudxognss/ui-picker`. 25개 용어 카드와 "애매할 때만 묻는" 계획은 그대로, 계획은 패널 대신 채팅의 표로 나온다.

## 사용

평소처럼 UI를 요청한다. 144컬럼보다 좁은 터미널에서는 패널이 스스로 못 열린다: 대신 애니메이션 미리보기가 브라우저에서 열리고, 질문은 채팅으로 오고, 숫자를 입력하면 답이 되며, `/ui-picker`를 치면 어느 폭에서든 패널이 열린다.

```
빵집 사이트 하나 만들어보자. 메뉴 부분은 멋지게.
```

모델이 페이지를 영역과 용어로 계획하고 패널을 연다:

```
⏺ ui-picker - ui_pick (MCP)(title: "빵집 사이트", ui: {
    "상단 내비게이션": "sticky-header",
    "메인 배너": "hero-section",
    "빵 메뉴": ["card-layout", "bento-grid", "tabs", "carousel"],   ← 질문
    "메뉴 카드": "hover-effect",
    "전체 레이아웃": "responsive-layout" })
  ⎿  { "review": true, "questions": 1 }

⏺ 오른쪽 패널을 확인하세요.
```

`2`를 누르면 벤토 그리드. 리뷰 보드에 다섯 행이 썸네일·패턴·누가 정했는지·숫자와 함께 뜬다. `3`으로 행을 열면 숫자마다 셀렉트, 메모 칸 하나.

![리뷰 보드에서 3번 행을 연 모습: 열 수, 강조 타일 크기, 간격, 메모](docs/edit.png)

`빌드`에서 Enter를 누르면 계획이 사용자 메시지로 모델에 간다:

```
ui-picker: build
- 상단 내비게이션: Sticky Header
- 메인 배너: Hero Section
- 빵 메뉴: Bento Grid (네 선택) · cols 3
- 메뉴 카드: Hover Effect
- 전체 레이아웃: Responsive Layout
```

모델은 정확히 그대로 만들고 행별로 보고한다.

![모델의 빌드 보고, 계획 행마다 한 줄](docs/build.png)

이후 `/ui-picker`로 보드를 다시 연다. 숫자를 바꾸거나 패턴을 교체하고 Enter를 누르면 바뀐 행만 `ui-picker: change`로 간다.

### 브라우저에서 초안 리뷰

HTML 초안에는 리뷰 오버레이가 들어간다. 열어서 아무 곳이나 클릭하고, 바꿀 점을 적고, **Copy for Claude**를 눌러 Claude Code에 붙인다. 각 계획 행의 루트 요소에 영역 이름이 붙어 있어서 메모가 맞는 행에 떨어지고, 행 안에서 클릭한 요소도 함께 기록된다.

![리뷰 오버레이: 메모 두 개와 붙여 넣을 메시지](docs/review-overlay.png)

```
ui-picker: change
- 빵 메뉴: "대표 타일에 사진 넣기" · h2 "오늘의 빵"
- footer.site-footer: "인스타그램 링크 추가"
```

오버레이는 HTML 옆의 스크립트 파일 하나(`ui-picker-review.js`), 의존성 없음, 새로고침해도 메모 유지. 초안이 확정되면 스크립트 태그만 지운다.

### 키

| 키 | 질문 중 | 리뷰 보드 |
|---|---|---|
| `1`-`4` | 그 후보 선택 | 1-9번 행 열기/닫기 |
| Enter | | `빌드` (또는 `변경 보내기`); 행 안에서는 셀렉트 확정 |
| `0` | | `빌드` |
| `x` / `r` | | 패턴 교체 / 행 초기화 |
| Esc | 남은 질문에 추천 적용 | 키보드를 입력창으로; 패널은 남음 |

질문이 열린 상태에서 입력창에 숫자를 치면 그 선택으로 친다. 다른 글을 치면 계획은 패널에 남고 모델이 답하거나 다시 계획한다.

## 언어

- 영어·한국어 패널 문구는 내장.
- 그 외 언어는 모델이 같은 호출에 패널 문구를 그 언어로 실어 보낸다. 용어 이름도 현지어(드로어는 ドロワー, 抽屉). 빠진 건 영어로.
- 빌드 메시지의 용어명과 키는 모든 언어에서 영어라서 생성 코드가 어디서나 같다.

## 동작 원리

1. **계획.** UI 요청이 `ui-vocab` 스킬을 깨운다. 모델이 모든 영역을 페이지 순서로 `영역 -> 용어 id`로 나열한다. 패턴 2~4개가 어울리는 영역은 질문이 된다(최대 3개).
2. **선택.** `ui_pick` 호출 한 번으로 패널이 열린다. 후보가 전부 동시에 움직이고, 숫자로 고르고, Esc는 추천을 적용한다.
3. **리뷰.** 행마다 썸네일·용어·출처 태그(`모델 판단`, `네 선택`, `추천 적용`, `변경`)·수정 가능한 숫자.
4. **빌드.** Enter가 계획을 사용자 메시지로 보내고 패널을 닫는다. 용어는 확정, 적힌 숫자는 기본값을 덮고, 메모는 네 지시.
5. **변경.** `/ui-picker`로 보드를 다시 열고, 바뀐 행만 `ui-picker: change`로 나간다. 브라우저에서는 리뷰 오버레이가 클릭과 메모를 같은 메시지로 바꿔 준다.

프로토콜 세부, 메시지 형식, 미리보기 내부, 라이브 체크리스트: [docs/reference.md](docs/reference.md) (영어).

## 동작 환경

| 환경 | 패널 + 질문 | 스킬만 (채팅에 표) |
|---|---|---|
| 터미널의 Claude Code CLI, 144컬럼 이상 | O | |
| 더 좁은 터미널 | 미리보기는 브라우저로, 질문은 채팅으로, 숫자로 답; `/ui-picker`로 패널 열기 | |
| Claude Code Desktop, VS Code 패널, `claude -p`, SDK | | O |

미리보기는 kitty 그래픽 터미널(Ghostty, kitty, WezTerm, Orca)에서 PNG 프레임, 그 외에서는 컬러 셀 아트. 위 스크린샷은 macOS의 Orca 1.4.

## 한계

- 얼리 액세스 mod API(`hooks.json` modules). Claude Code 릴리스 사이에 바뀔 수 있음.
- 요청당 `ui_pick` 1회, 영역 1-9개, 질문 최대 3개, 후보 2-4개.
- 수정 가능한 숫자는 용어 카드의 정해진 단계. 자유 텍스트는 메모로.
- 영어·한국어 외 언어는 호출당 패널 문구만큼 토큰이 더 든다.
- 어디에도 아무것도 보내지 않는다. 상태는 플러그인 세션 저장소에만.

## 저장소 구성

플러그인이 실행하는 것은 `.claude-plugin/`, `hooks/`, `skills/`, `types/`. 나머지는 개발용: `tests/`(플러그인 러너가 돌리는 125개 검사), `scripts/`(미리보기 프레임 재생성), `docs/`(스크린샷·프로토콜 문서), `tsconfig.json`.
